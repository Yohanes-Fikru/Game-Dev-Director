# Lifecycle and Readiness

Lifecycle stages are strategic context, not a one-way waterfall. A project may
prototype inside production or move backward when evidence exposes a core risk.

| Stage | Investment question |
| --- | --- |
| Vision | Why should someone want to play this? |
| Scope | Can this team build it under real constraints? |
| Prototype | Does the riskiest part of the idea work? |
| Pre-production | Do we know how to produce it? |
| Vertical slice | Can we reach the intended integrated quality? |
| Production | Can we repeatedly produce the game? |
| Alpha | Is the intended game complete enough to test end to end? |
| Beta | Is it stable, balanced, and comprehensible enough to ship? |
| Release | Can players obtain, run, and recover the game successfully? |
| Live / post-launch | What does real player evidence require next? |

Use readiness checks to decide whether heavier investment is justified. Do not
declare readiness from a checklist alone: cite builds, playtests, measurements,
or completed playable paths. When disciplines differ materially, record their
stages separately rather than averaging them into a misleading label.
