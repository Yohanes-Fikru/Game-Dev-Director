# Project Health

Use a health map when uneven maturity, hidden gaps, or cross-discipline risk
affects planning. Avoid it for tiny projects where one objective says enough.

Assess only relevant areas, such as vision, core gameplay, level/content design,
art, animation, audio, UI/UX, accessibility, technology, tools and pipelines,
performance, QA, production, and release readiness.

For each area record:

- evidence and current maturity;
- confidence in the assessment;
- the most important gap or dependency;
- whether it blocks the current objective.

Use words or coarse states (`unknown`, `exploring`, `repeatable`, `complete`,
`validated`) by default. If percentages are useful, define them as coverage or
maturity—not quality—and cite the evidence behind them.

End with no more than three cross-project risks and the one gap that most
changes the next playable objective.
