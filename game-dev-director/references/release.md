# Alpha, Beta, Release, and Post-launch

## Alpha

Validate the intended end-to-end game. Distinguish missing content from defects.
Stabilize save compatibility, progression, onboarding, and completion paths.

## Beta and release candidate

Control change. Validate target hardware, performance budgets, accessibility,
localization, platform requirements, install/update/uninstall, corrupted or old
saves, offline behavior where relevant, crash recovery, and support diagnostics.
Every accepted late change needs a concrete release benefit and regression plan.

## Release

Confirm the exact artifact, storefront/configuration, legal and attribution
requirements, rollback path, telemetry/privacy behavior, known issues, support
ownership, and launch communication. Run a clean-machine smoke test on what will
actually ship.

## Post-launch

Separate urgent player harm from noisy feedback. Prioritize data loss, crashes,
security, purchase/access failures, and hard progression blockers. Preserve
evidence, publish known workarounds when appropriate, and run a postmortem that
changes future decisions rather than assigning blame.
